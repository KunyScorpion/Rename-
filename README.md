## 1. アプリケーション概要・目的
本アプリケーションは、複雑なファイル名の構造を視覚的に分解・再構築し、一括置換（リネーム）ツールで使用するための「検索用正規表現」および「置換用文字列」を自動生成するツールです。
ユーザーは対象のファイル名を1つ入力するだけで、ドラッグ＆ドロップの直感的な操作で要素を並べ替え、括弧などの囲み文字を自由に変更できます。手作業ではミスが起きやすい正規表現の記述を自動化し、リネーム作業の効率と正確性を向上させることを目的としています。

## 2. 主要機能一覧（各画面の役割）
本アプリケーションはシングルページアプリケーション（SPA）として構成され、1つの画面内で以下の機能を提供します。

### ステップ1: ファイル名解析・入力機能
*   **役割:** 基準となるファイル名を受け取り、要素ごとに分解する。
*   **機能:**
    *   テキスト入力欄にファイル名を入力。
    *   「解析する」ボタン押下で、ファイル名を拡張子や空白、特定の囲み文字で構成される「パーツ」に自動分割。
    *   解析後はリセットボタンに切り替わり、いつでも最初からやり直すことが可能。

### ステップ2: ドラッグ＆ドロップ配置換え機能
*   **役割:** 分解されたパーツを直感的に再構成する。
*   **機能:**
    *   各パーツをドラッグ＆ドロップ（DnD）で任意の順番に並べ替え。
    *   各パーツをクリックし、ドロップダウンから囲み文字（`()`、`[]`、`【】`、`なし` など）を個別・自由に変更可能。

### プレビュー機能
*   **役割:** 再構成されたファイル名の最終結果を確認する。
*   **機能:**
    *   配置換えや囲み文字の変更をリアルタイムで反映したプレビュー文字列を表示。
    *   ワンクリックでクリップボードへコピー可能。

### ステップ3: 正規表現ジェネレーター機能
*   **役割:** リネームソフト等で利用できる正規表現を出力する。
*   **機能:**
    *   **検索文字列 (Find):** 元のファイル名構造にマッチする正規表現を自動生成。
    *   **置換文字列 (Replace):** 並べ替えた順序や新しい囲み文字の指定に基づく置換文字列（`$1`, `$2` の後方参照形式）を自動生成。
    *   それぞれワンクリックでクリップボードへコピー可能。

### その他補助機能
*   **テーマ切り替え:** ライトモード / ダークモードの切り替え（OS設定の自動検知および画面右上からの手動切替）。
*   **使い方ガイド:** 初回アクセス時や未入力時に、操作手順を分かりやすく表示。

## 3. 入出力仕様
### 入力仕様
*   **対象文字列:** 単一のファイル名（拡張子を含む文字列）
*   **入力例:** `(100) [あいうえお] ABCDE (@@).txt`
*   **制約事項:**
    *   空文字のまま「解析する」を押下した場合は、プレースホルダーのデフォルト値がパース対象として使用される。

### 出力仕様
*   **プレビュー文字列:** 変換後をシミュレートしたファイル名文字列（例: `[あいうえお] (100) (ABCDE) (@@).txt`）。
*   **検索用正規表現 (Find):** リネームツールで使用するための、キャプチャグループ（`()`）を用いた正規表現パターンの文字列。メタ文字のエスケープ処理も自動適用される。
*   **置換用文字列 (Replace):** キャプチャグループの参照（`$1`, `$2` など）を用いた文字列。

## 4. 解析・正規表現生成の構造（処理ロジック）
*※ 備考: 本アプリケーションはLLM（AIプロンプト）を利用した処理ではなく、独自の文字列解析アルゴリズムに基づく構造化処理を使用しています。以下はその解析および生成の内部構造です。*

### 4.1. ファイル名解析ルール
1.  **拡張子の分離:** 文字列の末尾から最初に出現する `.` 以降を拡張子として分離して保持。
2.  **パーツの分割:** 拡張子を除いたベース部分を、空白文字（スペース）や、特定の括弧（`()`, `[]`, `【】`, `<>`, `{}` など）を基準にして意味のあるチャンク（パーツ）に分割。
3.  **状態管理 (Partオブジェクト):** 各パーツに対して、以下のメタデータを付与して状態を管理。
    *   `id`: ドラッグ＆ドロップ識別用のユニークID
    *   `originalText`: 元の文字列
    *   `originalWrapper`: 元の囲み文字の種類
    *   `currentWrapper`: 変更後の囲み文字の種類（初期値はオリジナルと同じ）

### 4.2. 正規表現生成ルール
1.  **検索用正規表現 (Find Regex):**
    *   解析時の**元のパーツ順序**を元に左から順に構築。
    *   各パーツに対応する部分を `(.*?)` のようなキャプチャグループに変換（これが `$1`, `$2`... に対応する）。
    *   囲み文字がある場合は、正規表現として機能するようにエスケープ処理（例: `\[(.*?)\]`）を適用。
    *   セクション間は `\s+` （1つ以上の空白）や `\s*` （0個以上の空白）等で結合し、柔軟なマッチングを担保。
    *   先頭に `^`、末尾（拡張子前）に `$` を付与し、意図しない部分マッチを防ぐ。

2.  **置換用文字列 (Replace Regex):**
    *   ユーザーがドラッグ＆ドロップで指定した**新しいパーツ順番**に従って構築。
    *   元の位置に基づくキャプチャグループの番号（`$N`）を、新しい順序で再配置。
    *   ユーザーが変更した**新しい囲み文字**で該当の `$N` をラップする（例: 第2パーツの囲みを `[]` から `()` に変更した場合は `($2)` として出力）。
    *   パーツ間には適切な空白（スペース）を挿入し、最後に `.拡張子` を結合して完成。
